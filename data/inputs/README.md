# Demo input files

Sample files you can upload during a demo. Every person, e-mail (`@example.com`) and phone number (`90000000xx`) is fictional.
Skills and project titles match `data/sample_catalog/project_catalog_demo.csv`. Import that catalogue first so the projects exist.

## Report submissions (`submissions/`)

Each project has two versions of the trainee's report:

| File | Project | What it is |
|---|---|---|
| `solar_street_light_v1.pdf` | Solar Street Light Maintenance Drive | Weak first draft: short, no materials, no safety, no readings |
| `solar_street_light_v2.pdf` | Solar Street Light Maintenance Drive | Improved resubmission: aim, materials and tools, procedure, safety, results with numbers, conclusion, logbook hours and BOM |
| `domestic_wiring_board_v1.pdf` | Domestic Wiring Demonstration Board | Weak first draft |
| `domestic_wiring_board_v2.pdf` | Domestic Wiring Demonstration Board | Improved resubmission with all sections and test readings |

Demo flow:

1. Sign in as the student allocated to the project (Meena for solar, Ravi for wiring), open **Submissions** and upload `*_v1.pdf` as the report.
2. Wait for the automated report evaluation. It should score low and point out the missing sections.
3. As the supervisor, request rework on version 1.
4. As the student, upload `*_v2.pdf` as version 2. Its evaluation should be clearly higher, and both versions show in the **All versions** list.

## Regenerating

The PDFs are generated by `make_samples.py`, which also checks each PDF's text layer with pypdf. From the repo root:

```
backend/.venv/Scripts/python.exe data/inputs/make_samples.py
```
